6  Testing and Evaluation

6.1 Evaluation method and test data

Evaluation had two parts. The first was functional verification: does every requirement in Table 3.1 behave as specified, under the correct role, including the negative cases (a recruiter reaching another organisation's vacancy, an expired session, a duplicate application). The second was evidence from the deployed system: the same checks repeated against the production deployment — Convex production deployment elegant-wolverine-662, frontend at https://ise-three-jade.vercel.app — with screenshots captured from the live site rather than from a local build, because a local build proves nothing about the deployment.

Test data was generated by the project's own seeder (Appendix B). It creates two organisations, one administrator, two recruiters, 150 candidates with Nigerian names distributed across the three major ethnic groups in the intended proportions, six vacancies and 300 applications. Each application receives a generated PDF curriculum vitae, uploaded through the same signed-URL path a real candidate uses, then parsed and scored by the deployed functions. A subset of candidates carries a voluntary demographic declaration so that the audit has something to aggregate; the declarations are sealed with the production encryption key, exactly as a real declaration would be.
