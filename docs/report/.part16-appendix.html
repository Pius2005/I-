The split between audit, auditQueries, auditData and auditWrites is not arbitrary: Convex functions cannot call other functions directly, and a mutation cannot read aggregates while writing, so the read, compute and write phases are separated into modules that call each other through typed internal references. The same constraint explains why extract and secure are actions: they need the Node runtime for bcrypt, PDF parsing and cryptography.

Appendix B

Deployment and maintenance commands

The commands below reproduce the deployed system from a clean checkout. CONVEX_URL and SEED_TOKEN are environment variables; secrets are never committed. 

# 1. dependencies (workspaces: client, server, root)
npm ci

# 2. create or attach a Convex deployment (writes .env.local)
npx convex dev

# 3. production secrets — generate with:
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
npx convex env set --prod APP_SECRET <value>
npx convex env set --prod FIELD_ENCRYPTION_KEY <value>
npx convex env set --prod APP_URL https://<your-domain>

# 4. push functions to production
npx convex deploy

# 5. seed the demonstration dataset (development or a demo deployment only)
npx convex env set SEED_TOKEN <value>
CONVEX_URL=https://<deployment>.convex.cloud SEED_TOKEN=<value> \
  node scripts/seed-convex.mjs

# 6. type checks and static build
npx tsc -p tsconfig.convex.json
npm run typecheck -w client
VITE_CONVEX_URL=https://<deployment>.convex.cloud npm run build:web

# 7. deploy the SPA and alias the domain
npx vercel deploy --prod

# 8. local development against a dev deployment
npx convex dev            # terminal 1
npm run dev:web           # terminal 2

Operational notes

  • Non-ASCII project paths. The Convex CLI fails when the project path contains non-ASCII characters (the project directory is Iṣẹ́). Run deploy commands from an ASCII copy that links to convex/ and shared/.
  • Key rotation. Rotating FIELD_ENCRYPTION_KEY makes existing declarations unreadable, because the ciphertext is sealed with the previous key. The payload carries a version field so that a re-seal migration can be written; none is implemented in this version.
  • Seeding in production. Remove SEED_TOKEN from the production deployment once seeding is complete, so that the reset mutation cannot be called at all.
  • Retention. The scheduled function reads its window from settings; adjust it before handling real candidate data, and record the chosen window in the privacy notice.
