3.5 Feasibility study

Technical feasibility. Every capability required is available on the chosen platform: transactional mutations for stage changes, indexes for the pipeline and audit lists, file storage with signed upload URLs for CVs, Node-runtime actions for bcrypt and PDF text extraction, and cron functions for reminders and retention. The client needs nothing beyond a static host. No requirement in Table 3.1 depends on infrastructure the project would have to operate.

Economic feasibility. This was the decisive criterion. The previous stack combined four billed services: an application server, a managed PostgreSQL instance, object storage and an email provider. The database instance alone is charged continuously, which for a system that receives a few hundred applications per hiring season means paying for idle capacity eleven months a year. The replacement has exactly two billable surfaces — Convex function calls, storage and bandwidth, and Vercel static hosting — both with free tiers that cover normal departmental use, and both scaling with traffic rather than with the existence of a server. There is no monthly floor to budget for.
